# memclawrizer

Time-pressured flashcard/drill trainer (Electron + TypeScript + DuckDB). Pacing
mechanic from a 1990s vocabulary game, reskinned per Elena: an **arcade claw**
travels left → right as the visible timer while a kitchen-timer tick plays; answer
in time and the claw grabs a random trinket from a prize pit (session prize tray);
miss and a loud ding sounds and the card returns. Prizes fill a per-session **jar**
(one slot per card; first attempt decides prize vs. gray pebble — no percentages
shown). Perfect sessions seal the jar onto a permanent trophy shelf; imperfect jars
quietly empty back into the claw-machine pit at session end (prizes return to
circulation — "nothing kept", not "something lost"). No streaks, no instant retry. Elena memorizes only under time
pressure/stress or via logical attachment to known material — the timer and the
on-failure mnemonic display are the two pillars, not decoration. (Explicitly no
gun imagery — her request.)

First training sets: piano written notation → note names (SVG images) and Japanese
syllabaries → romaji (text). Content is pluggable via `.deckpack` (zip: deck.json +
media/); prompts may be text, image, or audio.

## Agent team & file ownership (build phase)
Work is split between a Backend agent and a Frontend agent working in parallel
worktrees, coordinated via `COORDINATION.md`. Ownership is exclusive:
- **Backend**: `src/main/**`, `src/preload.ts`, `scripts/**`, `decks/`,
  `test/**`, `package.json` + lockfile, `forge.config.ts`, `tsconfig.json`,
  `vite.main.config.ts`, `vite.preload.config.ts`, `vitest.config.ts`
- **Frontend**: `src/renderer/**`, `index.html`, `vite.renderer.config.ts`
- **Frozen contract**: `src/shared/**` — types + pure functions only (no Node, no
  DOM imports); changes require a request in COORDINATION.md and coordinator
  approval; additive only. Only Backend edits package.json; Frontend files dep
  requests in COORDINATION.md (it shouldn't need any).
- Docs (`CLAUDE.md`, `docs/*`, `COORDINATION.md`): shared, append-only sections.
- Commit prefixes: `[backend]` / `[frontend]` / `[shared]`.

## Key decisions (details & rationale in DESIGN.md)
- Stack mirrors `~/code/ayamt` (Electron Forge Vite+TS, main-process-owned DuckDB
  via @duckdb/node-api, hand-rolled migrations, minimal deps).
- Unlike ayamt, the DB is NOT a document: auto-opened from userData, since training
  state is per-person/per-machine. Content portability = deck packs.
- Leitner 5 boxes (1/1d/3d/7d/30d); only the first attempt per session moves boxes;
  failure resets to box 1 (classic). Timers tighten as box increases.
- Full audit log: every attempt (incl. in-session retries) with elapsed_ms, literal
  response, outcome, box before/after.
- Card/deck ids are author-chosen stable strings; re-import upserts and preserves
  Leitner state for existing card ids.
- One new dep allowed: `fflate` for zip packs. Media served to renderer via a
  custom `mem://` protocol (BLOBs from DuckDB), not IPC.
- Starter decks generated by scripts (`gen-kana.ts`, programmatic staff SVGs in
  `gen-piano.ts`) and imported through the normal pack path.
- Testing: bottom-heavy pyramid — pure-TS core (leitner, matching, drill state
  machine) with injected clock/RNG under Vitest; DB tests against real in-memory
  DuckDB (no SQL mocks); golden tests for deck generators; one Playwright-Electron
  smoke test for wiring; manual checklist for game feel. Details in DESIGN.md.
